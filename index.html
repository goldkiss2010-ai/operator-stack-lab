Operator Stack Lab

画像処理を「パラメータ」ではなく
「操作の列」として見る

露出、コントラスト、ガンマ、ブラー。画像編集では同じ操作を使っていても、並べる順番によって結果が変わります。Operator Stack Lab は、その処理の流れをカーブと実画像の両方から観察するためのブラウザ実験ツールです。

編集操作を、上から順に読む

一般的な編集ソフトでは、露出やガンマは個別のスライダーとして並んでいます。しかし実際には、それぞれの操作が信号へ順番に作用しています。このツールでは、その順序自体を主役にします。

カードはドラッグして並べ替えられます。順番を変えたとき、カーブと画像がどう変化するかをその場で確認できます。

使い方

1. 操作を追加する

露出、明るさ、コントラスト、ガンマ、Sカーブ、Gaussian Noise、Gaussian Blur などから操作を選びます。新しい操作は列の一番下に追加されます。

2. 強度を変える

各カードのスライダーでパラメータを変更します。数値入力も併用できます。変化はカーブと画像プレビューへ即座に反映されます。

3. 順番を入れ替える

カード右上のドラッグハンドルをつかみ、挿入したい位置へ移動します。挿入位置がハイライトされるので、処理順を視覚的に編集できます。

4. 画像で確認する

好きな画像を読み込むと、現在の操作列をそのまま適用できます。入力画像と最終出力を並べて比較できます。

画像はブラウザ内で処理されます。 この版は画像を外部サーバーへ送信する処理を持っていません。

一本のカーブで表せる操作

露出やガンマのように、ある画素の出力がその画素の入力値だけで決まる操作は、1変数関数として考えられます。

x → f₁(x) → f₂(f₁(x)) → … → F(x)

複数の pointwise 操作を積むと、最終的には一つの合成関数 F(x) として見ることができます。ツール上では、灰色の破線が入力 y=x、太い線が最終的な F(x) です。

解析欄では、局所的な増幅・圧縮を表す F′(x) と、曲率を表す F″(x) も確認できます。

Blurを入れると、一本のカーブでは足りなくなる

Gaussian Blur は、現在の画素だけではなく周囲の画素も参照します。そのため、単純な y=F(x) だけでは処理全体を記述できません。

I′(p) = Σ w(q) I(p+q)

ここで入力は一つの値ではなく画像 I になり、操作は関数というより「画像へ作用する作用素」になります。ツールに Blur や Noise が含まれている場合、カーブと微分は pointwise な部分だけを表示し、画像プレビューにはすべての操作を順番どおり適用します。

この違いが、Operator Stack Lab の中心的な見どころの一つです。Function Stack として始まった列が、空間処理を含むと Operator Stack へ拡張されます。

計算量も「1画素あたり」で見る

Big-O 記法だけでは、加算と log の違いは見えません。そこで解析欄では、理論計算量を併記しながら、1画素あたりの演算構成を相対的な cost units として表示します。

例：add / mul = 1, div = 3, pow / log / exp = 10

この値はCPUやGPUの実測時間を予測するものではありません。あくまで、同じツールの中で操作列どうしの重さを比較するための簡易指標です。Gaussian Blur では近傍参照数もコストへ含めています。

現在の制限

このツールは、画像処理の順序と構造を観察するための実験版です。現時点では、画像のRGB各チャンネルを基本単位として処理し、厳密なカラーマネジメントやscene-referred / display-referred の管理は行っていません。また、出力表示時には0–1範囲へクリップします。

そのため、色管理された現像・グレーディング環境の代替ではなく、「どの操作を、どの順序で作用させると、信号や画像がどう変わるか」を観察するための教育・実験ツールとして使うことを想定しています。
